Bugs Found in opencode-py
=========================

1. JSONC Parser - Nested Block Comments
----------------------------------------
File: opencode_py/config.py:62-64

The JSONC comment stripper doesn't handle nested `/* */` comments correctly. A comment like `/* outer /* inner */ */` will exit at the first `*/`, leaving the outer comment unclosed. While rare in practice, this is a correctness bug.

```python
while i < n and not (text[i] == "*" and i + 1 < n and text[i + 1] == "/"):
    i += 1
i += 2
```

---------------------------------------------------

```python

# Undo logic (lines 566-568):
if entry["original"] is None:
```

3. Session File I/O - Non-Atomic Writes
----------------------------------------
File: opencode_py/session.py:62-66

`save_session` writes directly to the session JSON file without atomic write (temp file + rename). If the process crashes mid-write or two sessions write concurrently, the file can be corrupted. `load_session` catches `JSONDecodeError` and silently returns `None`, losing the session data.

```python
def save_session(session: Session) -> Path:
    GPath.sessions_dir().mkdir(parents=True, exist_ok=True)
    path = session_path(session.id)
    path.write_text(json.dumps(session.to_dict(), indent=2), encoding="utf-8")
    return path
```

8. `_strip_jsonc` - Escaped Characters Inside Strings
-----------------------------------------------------
File: opencode_py/config.py:41-42

When encountering `\` inside a string, it skips the next character. If the escaped character is `\u` (Unicode escape), the subsequent 4 hex digits are treated as regular characters. If a comment sequence appears across a `\uXXXX` boundary, it could be misparsed. Very unlikely but theoretically possible.

```python
if c == "\\" and i + 1 < n:
    out.append(text[i + 1])
    i += 2
    continue
```

```python
while True:
    # ...

```

11. Auth - No File Locking on Concurrent Access
-----------------------------------------------
File: opencode_py/auth.py:57-73

The `_save()` method uses `tempfile.mkstemp` + `os.replace` for atomicity, but there's **no file locking**. If two processes call `set()` concurrently, they both read the current state, modify, and write - the second write overwrites the first. Since auth.json stores API keys, this causes silent key loss.

```python
def _save(self) -> None:
    import tempfile
    fd, tmp_path = tempfile.mkstemp(dir=self._file.parent, suffix=".tmp")
    # No flock/fcntl - race condition between read and write
    os.replace(tmp_path, self._file)
```

13. MCP Server - No Process Cleanup on Startup Failure
------------------------------------------------------
File: opencode_py/tools/mcp.py:38-60

If `subprocess.Popen` succeeds but `self.call("initialize")` fails, `close()` is called. But if the server process starts and then crashes immediately (before `initialize`), the process becomes a zombie - `close()` calls `terminate()` but may not reap it properly. Also, no `wait()` with timeout in `close()`.

```python
try:
    self.call("initialize", ...)
except MCPError:
    self.close()        # cleanup on init failure
    raise
```

16. Grep Tool - Regex ReDoS on Malicious Patterns
-------------------------------------------------
File: opencode_py/tools/grep.py:81-85

Python's `re` engine is vulnerable to ReDoS (catastrophic backtracking). Patterns like `(a+)+` or `(a|a?)*` on long input can hang indefinitely. No timeout or pattern complexity limit. The `rg` fallback avoids this but if `rg` is not installed, the Python fallback is vulnerable.

```python
try:
    regex = re.compile(pattern)
except re.error as e:
    return [("", 0, f"invalid regex: {e}")]
```

-------------------------------------------------------------------
File: opencode_py/tools/webfetch.py:37-39

HTTP URLs are silently upgraded to HTTPS, but there's **no certificate verification bypass**. If the HTTPS endpoint has a self-signed cert, it will fail. The upgrade is optimistic but may break for internal/local services. Also no option to disable upgrade.

```python
if upgraded:
```
